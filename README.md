# Text2Mdx

`Text2Mdx` generates Warcraft III billboard text models from text. It renders styled text to a texture, then writes a small `.mdx` model that references that texture.

## Build

```powershell
cmake -S . -B build
cmake --build build --config Release
```

The renderer uses DirectWrite/Direct2D, so this first version is Windows-only and needs a C++17 compiler such as Visual Studio Build Tools.

## Image Backend

The project now vendors the ResIL Windows SDK under:

```text
third_party\resil-sdk\ResIL-SDK-win32-2026-04-23
```

So the normal build will find ResIL automatically. You only need `TEXT2MDX_RESIL_ROOT` or `TEXT2MDX_RESIL_SDK_ROOT` if you want to point at another SDK:

```powershell
cmake -S . -B build-resil -DTEXT2MDX_IMAGE_BACKEND=ResIL
cmake --build build-resil --config Release
```

Values:

- `Auto`: prefer ResIL if found, otherwise use the internal BLP/TGA fallback.
- `ResIL`: require ResIL. ResIL is tried first, then unsupported save paths fall back to the internal writer.
- `FreeImage`: use the local FreeImage library for `.tga`/`.png`; `.blp` still uses the internal BLP1 writer because this FreeImage build has no BLP format enum.
- `Internal`: internal `.blp` and `.tga` only.

This ResIL SDK advertises BLP format support, but its current source tree exposes BLP loading without a BLP save branch. `Text2Mdx` therefore keeps Warcraft III BLP output reliable by falling back to the internal BLP1 palettized-alpha writer when ResIL reports an unsupported save. ResIL is still used for PNG output, and it is probed first for TGA/BLP. ResIL project page: <https://sourceforge.net/projects/resil/>.

The ResIL runtime DLLs are copied next to the executable after build:

```text
build-resil\Release\ResIL.dll
build-resil\Release\ins.dll
```

`Auto` does not use FreeImage unless you add `-DTEXT2MDX_ENABLE_FREEIMAGE_FALLBACK=ON`. The bundled local `FreeImage.lib` found on this machine is x86, while the default Visual Studio generator builds x64, so explicit opt-in avoids accidental architecture mismatch.

For this local static FreeImage build, use Win32 and the project will switch MSVC to the static runtime:

```powershell
cmake -S . -B build-freeimage-win32 -A Win32 -DTEXT2MDX_IMAGE_BACKEND=FreeImage
cmake --build build-freeimage-win32 --config Release
```

The default local FreeImage path is:

```text
E:\SynologyDrive\Project\库\freeimage
```

## Usage

```powershell
.\build\Release\Text2Mdx.exe --text "暴击!" --style crit --out ".\out\crit.mdx"
.\build\Release\Text2Mdx.exe --reference ".\out\crit.mdx" --text "烈火剑法" --out ".\out\fire_from_template.mdx"
.\build\Release\Text2Mdx.exe --text "烈火剑法" --style fire_skill --texture-format tga --out ".\out\fire.mdx"
.\build\Release\Text2Mdx.exe --list-styles
```

Default output is:

```text
out\name.mdx
out\Textures\name.blp
```

Every generated model also writes a sidecar template file:

```text
out\name.text2mdx.json
```

Use `--reference`, `--template`, or `--from-template` when you want to make one example model and then change only the text:

```powershell
.\build\Release\Text2Mdx.exe --text "暴击!" --style crit --out ".\templates\crit_example.mdx"
.\build\Release\Text2Mdx.exe --reference ".\templates\crit_example.mdx" --text "9999" --out ".\out\damage_9999.mdx"
```

When the reference was generated by `Text2Mdx`, the actual font, outline, glow, gradient, and texture format are read from the `.text2mdx.json` sidecar.

You can also point `--reference` at an external `.mdx` that has no sidecar. In that mode Text2Mdx records the external model path in the new sidecar, but it does not copy the external model shell; many Warcraft III effect models contain animated bones/materials that can make a swapped texture invisible in model editors. The output remains a static visible billboard text model. For easier local preview in War3 Model Editor, external references default to writing the texture next to the output MDX, such as `dunji.mdx` + `dunji.blp`. Since an arbitrary MDX cannot reveal the original font/outline/glow recipe, pass `--style <name>` if you want a specific text look:

```powershell
.\build\Release\Text2Mdx.exe --reference "E:\OpenClow\Warcraft III\war3mapimported\SHSZ_Ab.mdx" --text "盾击" --style crit --out ".\out\dunji.mdx"
```

## Styles

Styles live in `presets/styles.json`. The bundled presets are:

- `damage_red`
- `crit`
- `fire_skill`
- `machine_blue`
- `gold_name`

Each style controls font, weight, skew, fill gradient, outline, shadow, glow, padding, and model plane height.

## Notes

- The generated MDX is a billboarded textured plane, not real 3D text geometry.
- BLP output is BLP1 palettized with 8-bit alpha and power-of-two padding.
- If you request `--preview-png`, use the default `Auto` backend or build with `TEXT2MDX_IMAGE_BACKEND=ResIL`.
